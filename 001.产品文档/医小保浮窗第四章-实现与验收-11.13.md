# 医小保浮窗：业务文档第四章实现与验收

依据：《浦东新区医保智能体设计（业务侧）-11.12-V1.0》“四、进入左侧医疗机构监管履历画像栏目，医小保浮窗提示语”。本次业务规则优先于此前参考项目的通用引导说明。

- 列表页：使用完整欢迎语及4个指定快捷问题。
- 机构页：替换机构名称，展示该机构专属提示语和6个指定快捷问题，不重复列表欢迎语。
- 单次检查页：自动带入机构名称和检查批次，展示检查专属提示语及6个指定快捷问题。
- 名称统一为“医小保”，包含机器人提示、窗口标题和无障碍标签。
- 列表筛选以用户已提交的条件为准，同步名称、代码、风险等级、结算等级；未提交的草稿不影响分析。风险标签追加筛选时保留其他条件。
- “查询一家医疗机构”提供当前筛选范围内的名称/代码检索和定位；“比较两家机构”提供两机构选择，禁止同机构比较，复用横向对标分析视图。
- “解读当前页面”解释全区概况卡与筛选后列表的不同范围，展示当前筛选范围内的机构数量。
- 进入机构或检查详情后提示“已切换至…”，重新建立对应上下文，避免上一对象的数据混入。
- 快捷问题映射至现有监管分析能力，保留用户点击的原始问句，自动携带机构/批次；支持“为什么风险这么高”“和同类机构比怎么样”等省略对象的追问。
- 保留拖拽、位置记忆、收起会话、未读提醒和材料输入等已有浮窗能力。

验证命令（在前端目录运行）：

```sh
node tests/profile-assistant-guide.e2e.mjs
node tests/profile-assistant.e2e.mjs
npm run build
```

专项测试覆盖17项业务模型断言，以及三类页面文案、快捷问题、筛选条件继承、切换提示、当前机构风险归因及检查进度的浏览器交互。

## 11.13 欢迎语入口精简

按后续截图反馈，将列表欢迎语内六项能力改为可点击按钮；欢迎气泡与对话窗口共享同一组入口。点击后以原始能力名称发起对应业务对话。需机构的风险分析、区内排名、重点检查、监管建议和画像报告先引导选择目标机构，生成材料时先区分建议和报告。
移除列表初始欢迎语下重复的四个快捷按钮及“分析全区风险/展开重点机构清单”链接，移除对话窗顶部筛选/机构/批次说明；实际筛选继承和对象切换提示继续保留。机构页、检查页的专属快捷问题继续保留。
新增验证：`node tests/profile-assistant-capabilities.e2e.mjs`，逐项覆盖气泡和对话窗内的六项入口、机构选择后的分析衔接、重复控件移除及移动端布局。
