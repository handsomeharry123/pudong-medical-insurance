# 浦东新区医保智能体设计（业务侧）-11.12-V1.0

## 三、对话场景设计

### 场景一：全区监管概览

> P0 核心旗舰场景 | 展示浦东新区医疗机构监管的整体概况｜主打能力：全区监管问数、多维分析与逐级穿透
> 

**1.面向人群 · 场景 · 痛点 · 价值**

|  | **说明** |
| --- | --- |
| **面向人群** | 浦东新区医保局领导、一线工作人员 |
| **典型场景** | 领导希望快速掌握全区医疗机构风险分布、风险变化趋势、检查办理进度和重点监管对象；一线人员需要按风险等级、结算等级、检查类型、监管阶段等条件查询机构或检查记录，并逐级查看机构画像、单次检查和办理进度详情 |
| **核心痛点** | 医疗机构风险情况、历史检查记录和监管办理进度分散在不同系统，查看一家机构的完整情况往往需要跨系统查询、人工汇总。领导难以快速掌握全区哪些机构风险较高、哪些检查尚未完成；一线人员也难以快速找到需要重点检查的机构，及时跟踪检查进展和问题整改情况，容易出现风险情况掌握不全面、重点监管对象找不准、检查进度跟踪不及时等问题。 |
| **产品价值** | 用户通过自然语言即可查询全区监管结果、风险趋势和检查进度。智能体自动识别时间、风险等级、结算等级、检查类型、监管阶段等条件，生成数据大屏、趋势图和筛选列表，并支持从全区概况逐级穿透至机构画像和单次检查详情 |

**2.收益与交付物**

| **交付物** | 浦东新区医疗机构监管概况大屏、风险机构筛选列表、风险变化趋势图、结算等级风险结构图、检查监管进度看板、阶段检查列表、具体检查进度详情、办理时效与超期分析、重点监管任务清单 |
| --- | --- |
| **核心收益** | 将原本需要跨系统、跨表格完成的风险统计和进度查询转化为秒级问数与可视化分析；统一机构风险和检查进度统计口径；支持“全区—机构—检查批次”逐级穿透，兼顾领导掌握全局和一线人员定位具体任务的需求 |

场景一对话流程总体概览：

**流程图文字说明：**场景一以“欢迎语与四个快捷问题”为统一入口，向下分为A、B、C、D四条可独立进入的查询分支。A分支（1-A）查询全区医疗机构风险分布及变化趋势，第二轮可继续查看历史趋势、本月风险变化或区域分布，随后形成符合年度、区域或风险变化条件的机构名单；B分支（1-B）查询高风险或风险等级上升机构，第二轮可查看高风险名单、风险上升机构或分析共性风险，随后形成高风险、风险上升或符合指定风险维度的机构名单；C分支（1-C）按结算等级分析机构风险，第二轮可比较不同结算等级、查看指定等级或分析等级风险趋势，随后形成符合指定结算等级与时间条件的机构名单。A、B、C三条分支最终汇合至“用户选定机构—展示机构核心摘要”，再进入场景二“医疗机构监管画像”。D分支（1-D）查询检查办理进度及未办结检查，第二轮可查看未办结检查、指定监管阶段的检查或办理时间较长的检查，随后形成对应的检查名单；用户选定检查批次后，展示单次检查核心摘要，再进入场景三“单次监管检查详情”。整体流程区分“机构名单—机构摘要—机构画像”和“检查名单—检查摘要—检查详情”两条路径，不将机构选择与检查批次选择混为一体。

#### 5.1 A分支：全区医疗机构监管结果概况

**流程图文字说明：**A分支从1-A开始，用户提问“我想了解全区医疗机构风险分布及变化趋势”。图中示例回答为：截至2026年11月，全区124家机构纳入评级，其中高风险12家、中风险28家、低风险84家，本月5家机构风险等级上升；系统展示机构总数及高中低风险机构数4个概览指标、风险占比环形图和历年机构数量折线图，并设置“查看详情”入口，进入全区监管大屏。随后分为三条追问路径：①历史趋势路径（2-A1→3-A1）：用户询问近几年全区风险结构的变化，智能体总结历年高中低风险机构数量变化，指出高风险机构变化明显的年份；系统展示三类机构数量折线图、标注同比变化，并提供查看某年度高风险机构的快捷问题。用户继续查询“2025年高风险机构”后，展示该年度高风险机构及主要风险指标，表格包括机构名称、机构代码、结算等级、年度风险值和检查次数，用户可从中选择机构。②本月变化路径（2-A2）：用户询问本月哪些机构风险等级发生变化，智能体说明风险上升、下降和不变的机构数量，并列出等级变化机构；系统先给出文字结论，再展示包含机构名称、上月等级、本月等级和变化方向的表格，用户可直接从变化名单中选择机构。③区域分布路径（2-A3→3-A3）：用户询问高风险机构集中在哪些区域，智能体指出相对集中的街镇或片区；系统左侧展示机构风险点位图，右侧展示高风险机构数量前5的区域，并提供查看某区域高风险机构的入口。用户选定区域后，展示该区域高风险机构及整体风险情况，表格包括机构名称、机构代码、风险等级、最新风险值和最新检查，用户可从中选择机构。三条路径最终汇合至“查看A机构的具体情况”：智能体展示该机构当前风险等级、历次风险值均分、最新检查风险值、主要风险维度和最新检查情况；系统呈现机构核心摘要卡，并提供“查看完整机构画像”按钮，点击进入场景二“医疗机构监管画像”。图中的机构数量、年份及A机构等属于对话演示示例，不应作为固定业务数据写入实现。

#### 5.4 D分支：横向排名与对标

D分支内部只负责确定对标范围、统一口径、输出排名和差异结果。“为什么存在差异”不再放在D分支内部展开，而是作为进入C分支的入口。

D分支的业务边界：

1. 确定比较范围。
2. 统一比较口径。
3. 输出排名、分位和指标差异。
4. 用户需要解释差异时，再进入C分支。

**D分支流程图文字说明：** 本分支在已确定目标机构后，根据用户意图选择三类横向比较。①“全区排名”：统一数据时间和风险值口径，计算全区排名、分位及区内占比，说明风险值排名、处于前百分之几、违规费用排名和主要偏高维度；组件采用排名摘要卡与分位图，展示风险值、违规费用、风险等级及主要偏高维度。②“同类机构对标”：筛选同结算等级机构，统一时间、检查类型以及总额／次均口径，说明目标机构风险值与同类均值的差值、同类排名、违规费用差额及偏高最明显的维度；组件为同类机构排名表，以及目标机构与同类均值的对比条形图。③“指定机构比较”：先匹配用户指定的对标机构，再统一两家机构的统计范围和指标口径，比较风险值、违规费用高低与差额，并列出差异主要集中在哪些维度；组件为两机构指标对比表、风险值与违规费用分组条形图及主要差异维度列表。三类结果后均提供下一步操作：“解释差异”转入C，继承当前对标范围和差异维度继续归因；“查看相关检查”转入E，展示关联检查列表供用户选择；“生成建议或报告”转入F，继承排名、参照组和差异指标。D只输出可比口径下的排名和差异，不在内部展开原因分析。图中机构名称、名次、分位、均值、金额和维度均为示例或动态数据，不应写死。

#### 5.5 E分支：单次检查定位与概览

1. 定位用户要查看的检查。
2. 展示该次检查的核心结果。
3. 跳转场景三查看完整详情。

#### 5.6 F分支：监管建议与报告生成

**分支定位**

承接A至E分支已完成的分析，根据当前对话上下文生成监管建议或报告。用户不需要重新选择机构、时间范围、风险维度或对标对象。

**监管建议分为三个层级：**

1. 近期处置：需要优先核查、复核或跟进的事项。
2. 持续监测：需要观察趋势但暂不要求立即处置的维度。
3. 后续检查：下一次检查可重点关注的行为、项目和数据范围。

报告应只使用当前已完成且有数据依据的分析结果。用户尚未开展横向对标时，不应在报告中自动生成没有依据的排名结论；系统可提示用户先补充分析，或在报告中不纳入该章节。

#### 自动生成报告规则：

为便于研发实现，建议对报告生成设置以下规则：

1. **固定章节必须生成**
机构基本情况、风险总体概览、历次检查记录、数据范围与指标说明始终生成。
2. **可选模块按用户勾选生成**
未勾选的模块不出现在目录和正文中，后续章节编号自动调整。
3. **自动继承对话上下文**
继承用户已经确定的机构、时间范围、对标对象、重点风险维度和检查批次，不重复询问。
4. **缺少必要条件时先补问**
例如用户勾选横向对标分析但未确定参照组，应先询问比较范围，再生成报告。
5. **不得生成无数据支撑的结论**
没有有效数据时，显示“当前数据不足，暂不形成相关结论”，并取消对应图表。
6. **统一数据格式**
风险值保留两位小数；费用统一使用“万元”并保留两位小数；排名同时展示“第X名/X家”和分位水平。
7. **结论必须可追溯**
重点风险、监管建议等结论应关联对应检查批次、风险维度或违规项目。
8. **领导摘要后生成**
领导摘要应从报告正文提炼，不得出现正文中没有依据的新结论。
9. **支持对话修改**
用户可以通过对话增加、删除模块，修改时间范围、对标对象或章节详略，并生成新的报告版本。

A. 按监管机构查询：输入机构名称或机构代码，自动检索对应机构的监管检查记录。支持查询机构最新一次有效监管记录、全部历史监管记录，以及指定时间范围内的监管记录；支持按照单个机构、多个指定机构或全部监管机构进行查询。
B. 按时间范围查询： 支持按照指定日期、年度、季度、月份及自定义时间区间检索监管记录。例如，查询某机构本年度、本季度、近半年或截至目前的全部监管记录，自动识别时间范围并返回符合条件的记录。
C. 按批次及记录编号查询： 输入检查批次号、监管记录编号等唯一标识，直接定位对应监管检查记录。
D. 按监管阶段查询： 支持按照监管检查所处阶段进行筛选，包括网审分工、检查实施、形成结果等。
E. 按风险等级查询： 支持按照高风险、中风险、低风险等风险等级筛选监管记录。例如，查询某机构全部高风险监管记录，或查询全区所有中风险、低风险监管检查记录。
F. 按风险程度排序查询： 支持按照风险分值或风险等级对监管记录进行排序，识别风险最高或最低的监管记录。例如，查询某机构风险最高的5条监管记录，或查询全区风险排名前10的监管检查记录，并按照风险程度由高到低展示。
G. 按检查类型及监管结果查询： 支持按照检查类型、检查发现的问题、监管处理结论及整改情况等字段进行筛选。例如，查询某机构专项检查记录、存在违规问题的检查记录，或尚未完成整改的监管记录。具体检索维度根据系统实际数据字段确定。
H. 多条件组合查询： 支持上述检索维度自由组合，自动识别用户提出的多个查询条件，筛选符合全部条件的监管记录。例如，查询某机构本年度网审分工阶段的高风险监管记录，或查询全区本季度检查实施阶段风险排名前5的监管记录。
I. 模糊意图识别与交互引导：当用户提出的查询需求较为宽泛、存在多种可能的理解方式，或关键查询条件不明确时，智能体自动识别用户可能的查询意图，结合上下文分析提供2—4个合理的意图选项，引导用户进一步确认。
